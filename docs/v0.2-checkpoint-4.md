# v0.2 checkpoint 4: deterministic environment overlays

Status: complete and verified 2026-08-25.

DAGwright now compiles explicit environment variants without duplicating DataProduct contracts. A
`dagwright.io/v1alpha1` `DataProductOverlay` contains named, replacement-only JSON-pointer patches:

```sh
dagwright compile examples/customer-analytics/dataproduct.yaml \
  --overlay examples/customer-analytics/development.overlay.yaml \
  --target spark --output build/development
```

`--overlay` is repeatable on `validate`, `plan`, `compile`, `explain`, and `verify`. Disjoint patches
are sorted by overlay name and path before application, so reversing CLI arguments cannot alter the
effective normalized contract, canonical IR, or their digests.

The overlay boundary rejects:

- duplicate overlay names;
- duplicate or ancestor/descendant patch paths;
- missing targets, scalar traversal, and invalid list indexes;
- replacement of API version, kind, contract version, or DataProduct name;
- any effective document that fails strict DataProduct validation.

Overlays never mutate the source contract. They cannot add/delete fields, discover environments,
resolve secrets, persist history, or deploy artifacts. RFC-0005 records these compatibility rules,
and `schemas/dataproduct-overlay-v1alpha1.json` is included in source and wheel distributions.

Verification covered 92 standard tests, deterministic overlay goldens, Hypothesis argument-order
invariance, isolated-wheel overlaid compilation, both real Spark/Iceberg reference workflows, Ruff,
mypy, Pyright, schema/adaptor freshness, and dependency audit.
