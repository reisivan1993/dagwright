# DAGwright v0.1: deterministic Airflow/Spark/Iceberg compilation

Status: complete; scope corrected and verified 2026-08-24.

v0.1 proves the project thesis at the deterministic boundary: a hand-authored
`dagwright.io/v1alpha1` DataProduct contract becomes a strict normalized contract, canonical
engine-neutral IR, execution plan, and reviewable Airflow 3 plus Spark/Iceberg bundle with
reproducible digests. It does not require PostgreSQL, execute, deploy, or invoke a model.

## Install and verify

Install Python 3.12+ and `uv`, then run:

```sh
make install
make verify
uv run dagwright doctor
```

The locked development environment includes Airflow 3.3.1 so the generated golden DAG is imported
against the real `airflow.sdk` API during tests.

## Reference workflow

The hand-authored reference is
[`examples/customer-analytics/dataproduct.yaml`](../examples/customer-analytics/dataproduct.yaml).

```sh
uv run dagwright validate examples/customer-analytics/dataproduct.yaml
uv run dagwright plan examples/customer-analytics/dataproduct.yaml
uv run dagwright compile examples/customer-analytics/dataproduct.yaml \
  --output build/customer-analytics
uv run dagwright inspect build/customer-analytics/manifest.json
```

`validate` checks syntax, strict contract models, references, SQL, graph cycles, and adapter
capabilities. `plan` prints the NetworkX-derived stable topological plan. `compile` accepts
`--target airflow`, `--target spark`, or the default `all`, and writes only to an absent or empty
output directory. `inspect` verifies the size and SHA-256 digest of every manifest entry.

## Review bundle

Start review with `manifest.json`:

| Path | Purpose |
|---|---|
| `manifest.json` | Compiler/adapter versions, input digests, and digest/size of every artifact |
| `contract.normalized.json` | Default-resolved canonical contract |
| `pipeline.ir.json` | Canonical engine-neutral dependency graph |
| `plan.json` | Stable topological execution plan |
| `adapters/airflow/capabilities.json` | Exact capability snapshot used for validation |
| `adapters/airflow/manifest.json` | Airflow task metadata, delegated contracts, and lineage |
| `dags/dagwright__customer_analytics.py` | Readable Airflow 3 Task SDK DAG |
| `adapters/spark/manifest.json` | Spark/Iceberg workload artifact metadata |
| `spark/build_customer_engagement.py` | Generated PySpark SQL job |
| `iceberg/tables.json` | Deterministic Iceberg target metadata |

The top-level manifest cannot contain its own digest without becoming self-referential. The CLI
therefore reports the `manifest.json` SHA-256 separately. Every other emitted file is covered by the
manifest.

## Determinism

Normalization materializes defaults and sorts declaration sets. Canonical JSON uses UTF-8, sorted
keys, no insignificant whitespace, and no non-finite numbers. Stable URNs do not depend on source
ordering. SHA-256 is calculated over exact canonical bytes. Generated code and metadata contain no
timestamps, absolute paths, random values, or host data.

To verify reproducibility manually:

```sh
uv run dagwright compile examples/customer-analytics/dataproduct.yaml -o /tmp/dagwright-a
uv run dagwright compile examples/customer-analytics/dataproduct.yaml -o /tmp/dagwright-b
diff -ru /tmp/dagwright-a /tmp/dagwright-b
```

The end-to-end test performs this comparison and also compares every byte to the committed golden
bundle under `tests/golden/e2e/customer-analytics`.

## Supported and delegated semantics

The Airflow adapter preserves the schedule, `maxAttempts` retry intent, canonical dependencies,
quality gates, task metadata, operational contracts, and lineage. Batch is supported structurally;
CDC is delegated to the source implementation; freshness, volume, delivery, late data, and
watermarks are preserved in metadata and delegated to workload adapters. Streaming is rejected.
Capability violations include stable codes and IR paths.

The emitted DAG is deliberately fail-closed. Importing it constructs the graph, but task bodies
raise until later workload bindings exist. DAGwright v0.1 has no execute, deploy, apply, observe,
cancel, or rollback path.

## Public Python surfaces

- `dagwright.contracts`: strict models and JSON/YAML parsing;
- `dagwright.compiler`: normalization, canonical bytes/digests, IR, graph validation;
- `dagwright.adapters`: generation-only adapter types and manifests;
- `dagwright.adapters.airflow.Airflow3Adapter`: capability validation and artifact generation;
- `dagwright.review`: deterministic review-bundle construction and safe writing.

## Local Docker Compose demonstration

Compilation remains database-free:

```sh
docker compose run --rm compiler
```

The review bundle is written to `build/compose` on the host.

## Deferred work

Environment overlays and capability protocols for additional adapters remain backlog. PostgreSQL
is reserved for later operational history, approvals, deployments, and audit records; it is not a
local compiler dependency. Natural-language intake, model gateways, PydanticAI, agents, MCP, web UI,
n8n, automated repair/optimization, Temporal, Kafka, Kubernetes, vector databases, microservices,
Rust, and multiple orchestrators are v0.2-or-later work and have not begun.
