# v0.2 checkpoint 3: verification and release hardening

Status: complete and verified 2026-08-25.

This checkpoint makes local verification safe to author and useful when it fails. Before Spark
starts, DAGwright now requires fixture views to exactly match transformation inputs, rejects
unknown negative-control views and rules, and checks that deterministic ordering fields exist in
the expected schema and rows.

Negative controls declare `expectedFailures`. A control passes only when the actual failed rule IDs
exactly match that declaration. The customer reference executes all v0.1 rule types on Spark:

- `not_null`;
- `unique`;
- `accepted_values`;
- `expression`;
- `referential_integrity`.

Execution evidence now includes independent row and schema verdicts, per-control expected and actual
failures, and stable failure reasons. A wrong expected-output fixture intentionally returns exit code
1 while preserving parseable evidence containing only `rows_mismatch`.

## Verification commands

```sh
make verify
make verify-wheel
make verify-reference
make verify-reference-failure
```

`make verify-wheel` builds the source archive and wheel, installs the wheel and its dependencies in
an isolated environment, and exercises `version`, `doctor`, `validate`, Spark compilation, packaged
schemas, and suite parsing.

Contributor issue/PR templates, a release checklist, and an Apache-style readiness gap list are now
tracked in the repository. These practices do not make DAGwright an Apache Software Foundation
project. Public operation, community diversity, name clearance, signing, provenance review, and
multiple community releases remain prerequisites for any future incubation discussion.

No deployment, database persistence, agent, LLM, MCP, UI, additional orchestrator, microservice,
Rust, Kafka, Kubernetes, or Temporal capability is introduced.
