# v0.2 checkpoint 2: reusable verification suites

Status: complete and verified 2026-08-25.

DAGwright now accepts a strict `dagwright.io/verification-suite/v1alpha1` document and provides a
single compile-and-execute workflow:

```sh
uv run --extra execution dagwright verify PRODUCT.yaml \
  --suite VERIFICATION.yaml --output build/verification
```

The command validates the DataProduct and suite, generates only the selected Spark artifact,
executes it with local Spark 3.5 and Iceberg, and writes the compiled bundle, warehouse, and strict
execution evidence under the new output directory. Fixture paths are relative to and confined
within the suite directory. PostgreSQL and an orchestrator service are not required.

The suite declares:

- fixture file-to-Spark-view bindings;
- the generated transformation under test;
- expected rows, schema, and deterministic ordering;
- negative-control fixture replacements;
- at least two attempts for idempotency evidence.

The local evaluator implements the v0.1 `not_null`, `unique`, `accepted_values`, `expression`, and
`referential_integrity` rule contracts. Parameterized rules are rejected during contract validation
when their required values, expression, or reference is absent.

Verification remains deliberately local and deterministic. This checkpoint adds no deployment,
PostgreSQL persistence, agents, LLMs, MCP, UI, additional orchestrators, microservices, Rust,
Kafka, Kubernetes, or Temporal.
